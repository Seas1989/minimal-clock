# 时钟 · Minimal Clock

一个极简时钟 Web 应用：当前时间 / 倒计时 / 正计时三合一，支持多任务并发、**多个计时窗同屏挂开**、每日到每年的循环提醒、好友**同任务挑战**（各自打卡、按进度排行、点赞）、**网易云 / QQ 音乐听歌**（搜索单曲、自己攒列表）、自定义背景取景、**可拖拽重排、由自写弹簧物理驱动的面板布局**，而手机上则是**另一套形态**：整屏一页一个事、页面不滚、不给拖拽。
后端只用 Node 原生模块（`http` / `fs` / `crypto`），npm 依赖为零、没有构建步骤，克隆下来就能跑；前端不绑任何库，唯一一处第三方运行时是手机端外壳用的 Alpine.js（CDN，缺席也能用，见「手机端适配」）。

> 打开即用：`node server.js` → http://localhost:3000

---

## ✨ 功能特性

**时间与任务**
- 三种模式：当前时间（含日期星期）、倒计时、正计时（秒表）
- 多任务并发：每个任务独立计时，互不干扰，可任意时长（天/时/分/秒）
- **计时窗口坞**：任务点上 `▢` 就挂到主界面顶部，学英语时可以同时挂「英语」「学习」两个窗；点窗切换当前大表盘显示谁，点 `✕` 收起但**后台继续计时**
- **专注模式**：窗上的 `⤢` 把整页虚化，屏幕上只留下这一个计时
- **休息**：正计时按暂停时会问一句“要不要休息”，默认 5 分钟（1–30 可调）；休息结束时自动接回刚才的任务
- **听歌不只在休息里**：底部一条全局播放条，顶栏「▶ 听歌」或按 `M` 就开始（也可在音乐面板里点「▶ 播放这个来源」）；**只有进休息时会自动接着放**。内置轻音乐直接能播（无需任何配置），也可接入自己的网易云账号 / 指定歌单，走服务端只读代理
- **两个平台**：网易云与 QQ 音乐在音乐面板里一键切（QQ 音乐不需要任何 cookie）；**不限于“顺着歌单听”**——搜到的单曲可以整批连播、可以逐首搭自己的列表，播放条 ☰ 里点谁播谁、能单删，播放方式可切顺序 / 随机 / 单曲循环
- 循环任务：每日 / 每周 / 每月 / 每年自动滚动到下一轮，进度环同步
- 任务行**整行就是入口**：点名字、点时间、点行里任何空白都直接进专注；行尾 `▶` 走同一条路（开起来就进专注），`⏸` 只负责就地暂停
- **同任务挑战不在主界面**：收在顶栏「⚑ 挑战」（手机上是抽屉里那一格）后面的浮层里，卡片只给标题 + 一行名次摘要 + 状态，点卡片才进完整排行
- 完成提醒：提示音 + Toast + 浏览器标题闪烁，切了标签页也能发现；带挑战的倒计时跑完还会弹一块**结算画面**（最终名次 + 与第一名差多少）
- 今日进度条：一眼看到今天过去了多少

**协作**
- 注册 / 登录（scrypt 加盐哈希，token 鉴权）
- 好友申请（互发即成好友）
- **同任务挑战**：把一个目标发给好友，各自建自己的任务打卡，排行榜按**完成进度**排序、可互相点赞；邀请制，**对方可以拒绝**

**外观**
- 5 套主题底色（纸白 / 米沙 / 雾青 / 淡紫 / 夜黑）
- 自定义背景图：本地上传或外链，**焦点取景**式拖拽 + 缩放 + 顶部/中部/底部快捷选取
- 模糊虚化、遮罩强度、卡片浓度三档调节
- 文字颜色**按背景实际亮度自适应**，也可手动锁定深色/浅色字
- 面板可拖拽重排：捏住卡片边框即可拖动，其他面板被"挤开"，落位带果冻回弹与撕纸边缘动画
- **手机端是另一套形态**：≤ 760px 时整屏只显一个板块（时钟 / 任务 / 好友），顶栏 ☰ 拉开是整屏九宫格菜单，音乐、背景、挑战中心都是满屏 sheet；**页面本身不滚**，只有列表在自己那页里滚；面板拖拽在手机上关掉

## 🧱 技术栈

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 运行时 | Node.js ≥ 16 | 仅用 `http` / `fs` / `path` / `crypto` 原生模块 |
| 后端分层 | `server.js` + `lib/` | 入口只起服务；`lib/api.js` 分发，`lib/routes/*.js` 一个资源一个文件，无框架 |
| 存储层 | `lib/db.js` + `lib/store.js`（~285 行） | 内存真源 + 原子写 + `.bak` 自动回滚，无数据库依赖 |
| HTTP 工具 | `lib/http.js`（~72 行）+ `lib/auth.js`（~22 行） | 收发请求体 / 静态文件 / 密码散列与 token，不掺业务 |
| 挑战算法 | `lib/challenges.js`（~89 行） | 进度推导 / 排行 / 详情视图，纯函数，不碰 HTTP 与磁盘 |
| 音乐代理 | `lib/music/netease.js`（~274 行） | 只用 `node:https` 直连网易云网页端接口；解析函数全是纯的，断网也能测 |
| QQ 音乐代理 | `lib/music/qqmusic.js`（~176 行） | 同一套分层：单曲搜索 + vkey 直链，不需要登录态；同样纯解析、可离线测 |
| 测试 | `test/*.test.js` | 自己拉起服务 + 临时 DATA_DIR，137 项断言不碰真实数据、不碰外网 |
| 前端 | 原生 HTML / CSS / **ES Module** | 无构建、无打包、不引 bundler；`index.html` 只引一个 `js/main.js`，其余靠浏览器原生 `import`；**桌面端零框架** |
| 前端模块 | `public/js/*.js`（24 个，~2200 行） | 一个功能一个文件；模块体只放声明，接线集中在 `init()`，由 `js/main.js` 按固定顺序调用 |
| 手机端外壳 | Alpine.js 3.14.9（CDN，`defer`） | 全项目**唯一**一处第三方运行时，只管 `view` / `drawer` 两个状态；CDN 不通时退回 `js/mobile-shell.js` 里的原生绑定 |
| 手机端样式 | `public/css/mobile.css`（~270 行） | `<link media="(max-width: 760px)">`，桌面上浏览器根本不解析这个文件 |
| 动效 | `public/physics.js`（~110 行）+ 原生 CSS transition | 拖拽用自写弹簧积分（半隐式欧拉）；暂停缩放、图标交叉淡入这类微过渡一律交给 CSS，不引 GSAP / anime.js |
| 依赖 | npm 包 0 个；前端唯一第三方是 Alpine.js（CDN） | 项目不再把“依赖数为零”当对外卖点（`package.json` 里 `runtimeDependencies` 写明 Alpine 用在哪），但也没为此引库：这一轮的动画原生 CSS 就够用 |
| 数据 | JSON 文件（`data/`） | 首次启动自动生成目录 |
| 状态记忆 | `localStorage` | 主题、模式、背景、布局都存本地 |

```
│   ├── tasks.json      # 任务（按 owner 隔离，含所属挑战与窗口开关）

│   └── *.bak / *.bad-* # 存储层自动维护的备份与损坏留档（同样不入库）
└── scripts/            # ⚠️ 本机专用脚本（含本地绝对路径），同样不入库
    └── start-clock.bat # Windows 启动脚本
```

划分原则：**一个目录只回答一个问题** —— `server.js` 只管“怎么起服务”，`lib/http.js` 只管“怎么收发”，`lib/db.js` 与 `lib/store.js` 只管“数据怎么存”，`lib/routes/*.js` 按资源各管一组接口，`lib/music/*.js` 只管“上游怎么解析”，`public/js/*.js` 一个交互一个文件。两边通过 `/api/*` 通信；数据与本机脚本一律与源码隔离，`git clone` 出来的仓库永远是干净的代码。

## 🚀 快速开始

```bash
# 1. 克隆仓库
git clone https://github.com/Seas1989/minimal-clock.git
cd minimal-clock

# 2. 启动（无需 npm install）
node server.js          # 或 npm start

# 3. 浏览器打开
http://localhost:3000
```

可选：跑一遍端到端测试（自己拉起服务、用临时数据目录，不碰 `data/`）：

```bash
npm test                # 137 项断言：存储层 14 项（重启/并发/回滚）+ 挑战 32 项（进度/排行/邀请/点赞/迁移）+ 网易云 47 项 + QQ 音乐 44 项（解析/平台切换，都不联网）
```

换端口：

```bash
# Linux / macOS
PORT=8080 node server.js

# Windows PowerShell
$env:PORT="8080"; node server.js
```

数据目录位置也可通过 `DATA_DIR` 覆盖：`DATA_DIR=/var/lib/clock node server.js`。

## 🖱 使用说明

### 三种模式

| 模式 | 行为 | 循环 |
| --- | --- | --- |
| 当前时间 | 显示时分秒、日期、星期 | — |
| 倒计时 | 设定剩余时长，到点提醒；支持"结束后自动清零重跑" | 每日/周/月/年 |
| 正计时 | 从 0 开始累加，可暂停 | 每日/周/月/年 |

计时用**服务器时间戳差值**计算（`elapsedBase + (serverNow - startedAt)`），刷新页面、换设备都不会丢进度，也不会受本地时钟偏差影响。

### 好友

1. 顶栏注册一个账号（用户名 2–20 字符，密码 ≥ 4 位）
2. 好友面板输入对方用户名 → 发送申请；对方同样申请你一次即互为好友
3. 解除好友时，两人在挑战里互相的**待处理邀请**自动作废（已加入的历史进度保留）

### 同任务挑战（以前的“共享”重做了）

旧版共享是把同一个任务对象发给好友只读看，做到的是“一起完成同一份数据”；真正的激励应当是**同一个目标各自打卡**。所以现在：

挑战**不在主界面占一块地方**：顶栏一个「⚑ 挑战」入口（手机端收在抽屉里那一格），点开才是挑战中心列表，默认收起。

| 步骤 | 做什么 |
| --- | --- |
| 发起 | 任务上点 `↗` → 勾选好友（可多选、可全选）→ 发出邀请。倒计时自带目标量；正计时需额外给一个“每轮目标时长”（默认 30 分，5–600 可调） |
| 收到 | 列表里排在最前的就是待处理申请，**接受 / 拒绝** 两个按钮都能点；拒绝后不再出现，除非对方重新邀请 |
| 接受 | 自动给自己建一份**同目标的同名任务**，计时完全独立，谁也不能改谁 |
| 卡片 | 一行标题（最多两行，不做单行省略号）+ 一行小字 meta（发起人 · 目标量）+ 一行名次摘要「你排第 N / 共 M 人」+ 一行状态文案，卡片高度跟着内容走，没内容就不留白 |
| 状态 | 三种都写明白：**已满员** / **还差 N 人** / **你排第 N**（待处理邀请那条写「还差好友加入」） |
| 排行 | 点整张卡片进详情（其余界面雾化，没有单独的“查看”按钮）：完整名单按完成进度排序，名字 + 本周时长 + 名次，先显示前 5 行，其余点「还有 N 人」展开。排序先比刷完整了几轮，再比本轮跑了多少，最后比累计时长 |
| 点赞 | 每行一个 `♥`，再点取消；不能给自己点，未加入的人不能点 |
| 刷新 | 没有手动刷新图标。列表数据**每 30 秒自动拉一次**，且只在标签页可见时拉；列表上方一句不显眼的「刚刚更新 / N 秒前更新」自己走字 |
| 收尾 | 成员可“退出挑战”（任务保留），发起人只能“关闭挑战”（解绑所有人的任务，计时数据不删） |

进度不存历史表，全部从任务自身的 `elapsedBase` 推导：`cycles = floor(累计毫秒 / 目标毫秒)`，所以刷新、换设备、离线重连后排行仍然一致。卡片摘要、专注界面顶部那条窄排名条（`我第 N / 共 M，与第一名差 X`）、倒计时结束后的结算画面（最终名次 + 与第一名的差距）三处名次都走 `public/js/utils.js` 里的同一个 `rankOf()`，不会出现三个地方报三个数。

### 多窗口与专注

- **挂窗**：任务行上点 `▢`，这任务就出现在主卡片顶部的窗口坞；再点一个就是两个窗同时跳。`window` 开关存在服务端，换设备登录也一样
- **切窗**：点某个窗 → 自动跳到对应标签页并把大表盘切给它，当前那个窗描白边
- **收窗**：`✕` 只是从屏上拿掉，**后台接着跑**，再点 `▢` 挂回来时进度一点不少
- **进专注**：任务行**整行可点**（包括标题和时间之间的空白），点进去就是专注；行尾那个 `▶` 走的是同一条路径（非计时中＝开起来并进专注，计时中＝只暂停）
- **专注**：整页 `backdrop-filter: blur()` 雾化，只留下这一个计时（大字时间 + 进度条 + 开始/暂停/重置），任务在挑战里时顶部另有一条窄排名条；`Esc` 或“退出专注”回到普通界面
- **新建任务时**：窗口坞还是空的会自动挂上第一个窗，不用多一步

### 休息（只给正计时）

正计时跑到一半想喘口气，不该逼着自己去记“刚才跑到哪了”：

| 行为 | 说明 |
| --- | --- |
| 触发 | 正计时任务一按暂停（控制面板 / 任务行 / 空格三个入口都算）就弹窗询问“休息 N 分钟？”；倒计时不问，它本来就是定时的 |
| 界面 | 全屏雾化层，复用专注模式的样式：大字倒计时 + 进度条 + “休息结束后继续「某任务」” |
| 时长 | 默认 5 分钟，层内滑块 1–30 可调（存 `localStorage`）；休息中拖滑块按新时长重算，另有 `＋1 分钟` 可临时续 |
| 结束 | 归零 → 提示音 + 自动 `resume`；提前点“结束休息”则不续，只收层 |
| 音乐 | 播放条是全局的，进休息时浮在这一层底下接着放；**只有休息会自动开始放**，普通界面要你主动点；自动放的是“当前列表”（来源拼的、搜的、自己攒的都算） |
| 退出登录 | 只收起休息层，不会替你把任务重新跑起来 |

任务自身的计时仍然老实停在 `elapsedBase` 上 —— 休息状态是**纯前端**的，刷新页面、换标签页都不会污染进度，挑战排行也不受影响。专注层里按暂停也问得出休息，靠的是确认弹窗层级（`z-index: 50`）压在雾化层（20）之上。

### 音乐（网易云 / QQ 音乐）：任何界面都能听，只有休息时自动放

轻音乐不用自己找：两个平台默认都有一份内置队列，**不填任何配置也能直接响**（只需在本应用里登录）。顶栏点「音乐」打开设置面板，最上面先选平台：

| 平台 | 能放什么 | 要登录态吗 |
| --- | --- | --- |
| 网易云（默认） | 内置轻音乐 / 别人的公开歌单 / 自己的收藏歌单 / 搜单曲 | 只有“自己的歌单”与 VIP 曲目要（粘 `MUSIC_U`） |
| QQ 音乐 | 内置轻音乐 / 搜单曲 | **完全不用**，但读不到歌单（下面细说） |

选了平台，下面的「来源」与搜索都跟着走这个平台；换平台会清掉当前列表——曲目 id 两边不通用（网易云是数字、QQ 是 `songmid` 字符串），留着旧列表只会在取地址时全线失败。

**网易云的三种来源**

| 来源 | 说明 |
| --- | --- |
| 轻音乐（默认） | 不写死歌单 ID。先用“歌单搜索”试几个候选词（轻音乐纯音乐 / 纯音乐钢琴治愈 / 轻音乐），**取曲目最多的那个**歌单；全失败则退回单曲搜索 |
| 我的歌单 | 需填 MUSIC_U。读到你自己的歌单列表，点“用它”就锁定那份 |
| 指定歌单 | 直接粘网页地址栏（`...playlist?id=xxx`）或纯数字 ID，别人的公开歌单也行 |

弹窗里还能直接搜歌：搜到的单曲**不再只是“试听一声”**，而是能整批连播、逐首攒成自己的列表（见下面“不想顺着歌单听”）。

**底部播放条（只跟着“有没有队列”出现，不放东西时页面还是原来的极简）**

| 控件 | 作用 |
| --- | --- |
| 顶栏「▶ 听歌」/ `M` | 开始放当前来源；正在放就变成「⏸ 听歌」，再点一下只暂停，**不重新拉队列**（否则每次都从随机那首开头） |
| ⏮ / ⏭ | 上一首 / 下一首（队列环形，到尾自动回到开头；随机模式下 ⏮ 走历史栈往回退） |
| ▶ / ⏸ | 暂停与继续；卡在“都取不到地址”时点它就是重试 |
| ☰ n | 展开 / 收起当前播放列表（n 是列表里的首数） |
| 🔁 | 播法循环：🔁 顺序 → 🔀 随机 → 🔂 单曲循环（存 `localStorage` 的 `playMode`） |
| ✕ | 停止并收起播放条（清掉列表与地址，不自动复活） |
| 进度条 | 整行可点，点哪就跳到哪 |
| 标题两行 | 上行歌名（出错时换成失败原因），下行“来源 第 n/N 首 · 歌手 · 0:32 / 4:05” |

**不想顺着歌单听：搜单曲、点谁播谁、随机**

| 位置 | 能做什么 |
| --- | --- |
| 搜索结果上方 | 「▶ 连播这 N 首」把整批单曲（最多 30 首）一次收进列表 |
| 搜索结果的单曲行 | 「播放」= 从这首开始连播这批；「＋」= 只加进列表，不打断正在放的这首 |
| 搜索结果的歌单行 | 「播放」= 直接放这个歌单（走 `/api/netease/playlist`，仅网易云有）、**不改**「休息时放什么」；「设为来源」才是改配置 |
| 播放条 ☰ | 展开当前列表：点任意一行立刻切过去放，行尾 ✕ 单删一首；删的正是当前这首就顺势接着放下一首 |
| 播放条 🔁 | 🔁 顺序 → 🔀 随机 → 🔂 单曲循环 |

随机抽的是“本轮还没抽过的”，一轮内不重复、用完自动重开；⏮ 走历史栈往回退——不然随机模式下“上一首”根本回不去。列表整体存在 `localStorage`（`musicQueue`，只存曲目摘要、不存直链，直链几小时就过期、重启时按 id 现取），所以刷新后 ☰ 还在、点 ▶ 接着从这首放；点 ✕、换来源、退出登录都会把它清掉。

谁在放、什么时候收得住，由一个 `music.owner` 标记决定：

| 场景 | 行为 |
| --- | --- |
| 进休息时**没在放** | 自动拉队列开始放，`owner = rest` |
| 进休息时**已经在放** | 不打断、也不把当前这首从头放起，`owner = user` |
| 休息结束 | `owner = rest` → 替他收掉（停止 + 藏条）；`owner = user` → 接着放 |
| 休息里手动点过 ▶ | 算 `user`，休息结束不再替他关 |
| 退出登录 / 点 ✕ | 直接收摊（`musicStop`），不留下“声音还在、控件没了”的状态 |

在音乐面板里换了来源（轻音乐 / 指定歌单 / 我的歌单）：正在放就**顺着切到新队列**，而不是留个对不上的旧队列；只改 MUSIC_U 不动当前播放。

**QQ 音乐这边：边界是探出来的，不是猜的**

没有 QQ 登录态时，它的网页端接口只有一小部分能用，所以这个平台只做“内置轻音乐 + 搜索单曲”：

| 接口 | 实测结论 |
| --- | --- |
| `soso/fcgi-bin/client_search_cp` 单曲搜索 | 不要 cookie，`n=30` 就给 30 首；字段 `songmid / songname / singer[].name / interval(秒) / pay.payplay` |
| `musicu.fcg` 的 `vkey.GetVkeyServer / CgiGetVkey` | 地址**不在返回顶层**，而在 `req_0.data.midurlinfo[].purl`，直链 = `sip[0] + '/' + purl`；免费曲给得出、付费曲 `purl` 为空 |
| 各类歌单接口（`client_music_search_songlist` / `fcg_music_fcg_getclientdiss` / `music.playlist.*`） | **没 QQ 登录态一律读不到**（-3002 / 404 / 500003），所以 QQ 侧根本没有歌单路由；想放自己的歌单就切回网易云 |

`pay.payplay === 0` 与“拿得到 purl”实测一一对应（抽样 12/12），所以 QQ 的内置队列直接只留免费曲目，搜索结果也照这个把付费歌标成「· 需会员」并排到后面。音频直链实测不校 Referer/Origin/Cookie、支持 Range（206），拿到就交给 `<audio>`，音频字节不经过本机。

**怎么取 MUSIC_U（网易云唯一的“登录”方式；选 QQ 音乐就完全不用碰这节）**

先说清楚要填的是什么：`MUSIC_U` 是网易云发给已登录浏览器的一串**身份 cookie**（约 400 字符），拿到它就等于拿到你那个号的登录态。本应用只用它做两件事——读你自己的歌单列表、取 VIP 曲目的播放地址，不会拿去做任何写操作。

1. 电脑浏览器打开 <https://music.163.com/> 并登进**网页**（只在手机 App 里登录不算，App 里取不到这串）
2. 在该页面按 `F12` → **Application（应用）** 标签 → 左侧 **Cookies** → 点 `https://music.163.com`
3. 找到 Name 为 `MUSIC_U` 的那行，复制 Value，粘进「音乐」面板最下面那栏 → 点「保存」

嫌一步步找麻烦，就把 **Network（网络）** 标签里任意一条 music.163.com 请求的整行 `Cookie:` 复制进来，服务端只挑其中的 MUSIC_U、其余丢掉。同样的步骤在音乐面板里点开「MUSIC_U 怎么取」随时能看。

| 想听什么 | 要填 MUSIC_U 吗 |
| --- | --- |
| 内置轻音乐 | 不用 |
| 别人的公开歌单（粘链接或 ID） | 不用 |
| 我自己的收藏歌单 | 要 |
| VIP / 付费专辑曲目 | 要，且那个账号本身有相应权益 |

这串通常几十天过期。过期后接口会明说「MUSIC_U 无效或已过期，去网易云网页端重新登录后再复制」，照上面重来一次即可；不想折腾就把它晾着，内置轻音乐照常能听。

**为什么不做扫码 / 验证码登录**：网易云那几个登录接口要么要求 weapi 的 RSA+AES 签名，要么得把登录二维码交给第三方生图服务（等于把你的登录链接递出去），都和“只做只读代理、不把账号信息往外递”的定位冲突，实测 `/api/login/qrcode/unikey` 还能拿 key、但 `create` 与 `check` 已经走加密通道了。真要加，见文末“可扩展方向”。

**实现要点**
- **一个配置接口、两个数据接口前缀**：平台 / 来源 / MUSIC_U 合成一条记录走 `/api/music/config`；数据路由按平台分 `/api/netease/*` 与 `/api/qq/*`，两边形状一致（search / url / queue），前端只是拼一个平台前缀。QQ 侧**没有**歌单类路由（读不到，见上节）。
- **MUSIC_U 只存服务端**（`data/settings.json`，不入库）：浏览器直接请求网易云会被 CORS 拦住，所以搜索/歌单/地址全部走服务端代理。音乐接口**全部需要登录本应用**，免得本机被当成公开代理用（QQ 不要 cookie，但也要登录后才能调，同样是这个理由）。
- **永不回传明文**：配置接口只给前 6 后 4 的打码指纹（`ABCDAB…ABCD`），用来核对“粘对了没”；粘贴时连整条 Cookie 一起复制也能用，服务端只取其中的 MUSIC_U。
- **不填 cookie 也能听**：网易云 `fee=1/4` 的 VIP 歌在没有 cookie 时大概率取不到地址，排在队列后面；`fee=8`（免费试听）实测能直接播，归为可播一档。QQ 则直接用 `pay.payplay` 判。**两个平台的单曲结果都走这一步稳排**：否则搜个歌手连播，前 5 首全是付费歌，看起来就像功能坏了。
- **取不到就跳**：连试 5 首都拿不到地址才停，并把原因写在标题位（“连着 5 首都是付费歌，填入 MUSIC_U 后才能播” / “要 QQ 音乐会员”），而不是弹五个错误框。
- **不做流量代理**：两个平台的 CDN 直链实测都不校 Referer、支持 Range（拖动进度）、`http` 能直接升级成 `https`，所以拿到地址就交给 `<audio>`，音频字节不经过本机。
- **歌单曲目要两次拼**（仅网易云）：`/api/playlist/detail` 现在只吐前 10 首（连 `trackCount` 都只报 10），所以再用 `/api/v6/playlist/detail` 拿完整 id 清单、`/api/v3/song/detail` 一次 50 首批量补详情。
- **自动播放的关卡**：Safari 只把“用户手势那一次同步调用”当回事，所以在点「▶ 听歌」与进休息层的**同步路径**上先用一段 0 采样的静音 WAV 把 `<audio>` 碰响（只做一次，`dataset.unlocked` 标上就再也不碰），拉完地址再换 src 才不会被拦下。
- 音量存 `localStorage`（`musicVol`）；队列起点每次随机，不至于每段休息都从第一首开始。

### 背景美化

点顶栏「背景」打开设置面板：

| 控件 | 作用 |
| --- | --- |
| 上传本地图片 | 走 `FileReader` 转 dataURL，图片不出本机 |
| 图片地址 | 粘贴任意 https 外链，回车应用 |
| 铺满 / 完整 | 对应 `cover` / `contain` 基准适配 |
| 缩放（100–400%） | 滑块或直接在小框上滚滚轮 |
| 取景位置：顶部 / 中部 / 底部 | 放大后一键只看想展示的那一段 |
| 拖动小框 | 1:1 跟手取景，双击回到正中 |
| 模糊虚化（0–30px） | 背景太抢眼时虚化一下 |
| 遮罩强度（0–80%） | 压暗背景，保证文字可读 |
| 卡片浓度（30–95%） | 卡片自身底色的不透明度 |
| 文字颜色：自动 / 深色字 / 浅色字 | 自动模式下按亮度判定，也可手动锁死 |

**实现要点**
- 取景用**焦点模型** `fx / fy ∈ [0, 1]`（等价 `background-position` 语义）：可拖行程 `over = max(0, 图片尺寸 − 视口尺寸)`，偏移 `x = −over × fx`。所以放大 400% 后依然能拖遍全图，也能精确停在顶部或底部；未放大的轴行程为 0 时自动居中，不会被"卡住"。
- 几何**只在视口坐标系算一次**，预览小框用 `transform: scale()` 做等比镜像映射，因此"小框里看到的"和"全屏实际显示的"严格一致。
- 外链图片若因 CORS 无法采样亮度，会退回中性估计并依赖遮罩/卡片浓度保证可读性。

### 面板布局（可拖拽重排）

点顶栏「布局」打开面板，或直接开拖：

- **抓边框起拖**：每张卡片四边有 10px 命中区（触屏加宽到 22px），右上角还有点状提手，鼠标变成 `grab` 就能拖
- **弹簧跟手**：卡片不是直接贴在指针上，而是被一根“很硬的弹簧”（刚度 1050 / 阻尼 48）拖着追指针 —— 急转向时会跟不上半步再追回来，就有重量感了
- **挤让位**：拖动时其他面板的位移不是 CSS 过渡，而是把布局跳变的差量当作“初始偏移 + 保留原有速度”交给弹簧回拉，连续挤压会**累积动量**，越挤越“撞”；插入位置由虚线占位符指示
- **惯性甩出**：松手时把卡片自身速度注入落位弹簧，快抛出去会过冲一段再弹回，慢放则直接归位
- **果冻质感**：形变与倾角取“手的即时速度”驱动 `skewX / scale / rotate`，横向拖得快就斜着拉长，一停就弹回（形变弹簧的静止阈值收到千分级，否则末尾“弹回原尺寸”会被当成误差直接跳掉）
- **撕纸边缘**：拖起时圆角被替换为每 ~90ms 刷新一次的不规则多边形 `clip-path`，毛边幅度随拖拽速度涨；落位后逐帧收敛再恢复圆角
- **橡皮筋边界**：拖出可用区不会硬停，而是按 iOS 橡皮筋公式越拉越沉，能拽出去一点但脱不了缰
- **列宽挤压**：拖动两列之间的竖条，另一列被“挤窄”（220–620px）
- **模板**：经典（右栏）/ 侧栏居左 / 单栏，一键切换并带动画过渡
- **目标列高亮**：拖到哪一栏，那一栏就亮起虚线框，松手前就知道会落在哪
- **不会互相盖住**：所有面板与列都是 `flex-shrink: 0`，宁可让页面滚动也不把卡片压到比内容还矮（压扁会让溢出内容画到下一张卡片上，看起来像两个面板占了同一位置）
- **打断也能落位**：触屏被系统手势打断（`pointercancel`）、拖到一半切窗口（`blur`）都会正常落位；万一残留，下次加载会把飘在 `body` 上的卡片接回归属列并清掉内联定位
- **省电**：全部弹簧共用一条 `requestAnimationFrame` 心跳，静止后自动停摆，不空转
- **恢复默认**：布局弹窗内可一键重置

布局结果存 `localStorage` 的 `layoutV2`，重开浏览器保持不变；数据异常时自动回落到默认布局。没引入第三方物理库（GSAP / matter.js 与“无构建、打开就能跑”的定位冲突），`public/physics.js` 一百行写完。代码位：存档读写在 `public/js/layout.js`，拖拽本身（热区装配、跟手弹簧、挤让位、落位动画、列宽挤压）在 `public/js/panel-drag.js`；手机不装热区就在那文件的 `if (!isMobile())` 一行上，不是删了拖拽，是只给桌面装。

### 手机端适配

手机上的要求不是“把桌面挤窄”，而是三条硬的：**不用拖动**、**大小刚好一屏**、**不要上下滑动**。所以 ≤ 760px 干脆换成另一套形态，由 `public/css/mobile.css` + `public/js/mobile-shell.js` 驱动。

**形态：整屏一页一个事**

| 位置 | 手机上变成什么 | 怎么做到的 |
| --- | --- | --- |
| 顶栏 | 只剩 `☰` + 标题 + 主题色圆点；「布局 / 背景 / 听歌 / 音乐 / 挑战 / 用户名 / 退出」收进抽屉 | `body.mobile` 下那几个按钮 `display: none`；入口在抽屉里，抽屉里的「音乐 / 背景美化 / 同任务挑战」直接 `.click()` 顶栏那个按钮，复用现成的打开逻辑 |
| 三个全屏页（时钟 / 任务 / 好友） | 叠成同一屏，一次只显示一个，**等于全屏页**；标题跟着变成「← 任务列表」，点它回时钟页。挑战不在这三个里，它是个满屏 sheet | `.col { display: contents }` 让列盒模型消失 + 卡片 `position: absolute; inset: 6px 8px 6px`，显隐只认 `body[data-view="…"]` |
| 抽屉（`☰`） | 整屏九宫格：3 个页面 + 同任务挑战 + 音乐 + 背景美化 + 听歌 + 退出，当前那页描边高亮 | `#drawer` `position: fixed; inset: 0`，z-index 40（盖住弹层 10 / 专注 20 / 播放条 25，但确认框 50 仍压得住它） |
| 弹层（音乐 / 背景 / 挑战中心 / 挑战详情 / 结算…） | 满屏 sheet，「完成 / 关闭」那一排吸底；播放条露在外面时按钮自动抬高一条 | `.modal-box` 拉到 `min-height: 100dvh`、抹掉圆角与投影，`.modal-actions` `position: sticky; bottom: 0`；`body.has-player` 时 `bottom: calc(112px + safe)` |

**外壳用 Alpine.js（本项目唯一一处第三方运行时）**

只让它管两个状态：当前哪一页（`view`）与抽屉开没开（`drawer`），绑成 `body` 上的 `data-view` / `data-drawer`；页面长什么样全在 `mobile.css` 里由这两个属性决定。状态真源存在 `js/mobile-shell.js` 的普通变量里，Alpine 只是它的绑定镜像，所以：

- **不把 `public/js/` 那两千多行渲染重写第二遍**，抽屉只是多一层路由；
- **CDN 不通也不瘫**：`defer` 的 Alpine 没就绪时，`js/mobile-shell.js` 用同一批 `data-*` 属性补上原生 click 绑定，只少“当前页高亮”这一点视觉；两套绑定同时存在时靠 `if (shellRef) return` 守卫，不会把「听歌」点成开始又立即暂停；
- 两层保险各管一半：`<link media="(max-width: 760px)">` 挡住桌面（避免 JS 没跑时桌面被误改），`body.mobile`（由 `matchMedia` 打）挡住“JS 挂了 / Alpine 没加载”——这时退回下面那张表里的老手机布局，功能照常可用。

为什么不是“另外做一套移动端页面”：数据、鉴权、音乐队列全在同一批模块里，第二套页面必然要复制这些逻辑，改一处忘一处。手机与桌面共用同一份 DOM 与状态，差别只在 CSS 与一层外壳。

**窄屏细节**（旧版就有的那些坑，仍然是下面这套退路形态与触屏拖拽要守的规则）

| 现象 | 原因 | 做法 |
| --- | --- | --- |
| 主题色圆点看不见、切不了颜色 | 顶栏是一行不换行的 flex，窄屏上整行溢出，圆点被挤出屏幕右侧 | `header` / `.header-right` 允许换行，圆点在手机上放大到 26px |
| 浏览器地址栏和页面颜色割裂 | 没声明 `theme-color`，手机浏览器只能猜（一般猜白） | 切主题时由 JS 动态写入 `meta[name=theme-color]`；有背景图时按压暗后的亮度取深/浅 |
| 两栏被挤成牙签 | 侧栏写死 `--side-w`（220–620px），窗口 820px 时主栏只剩 440px | ≤ 1024px 时侧栏取 `clamp(220px, 32vw, var(--side-w))`，跟着视口缩但不低于 220px |
| 手机上还是左右两栏 | 桌面布局被 `localStorage` 带过来 | ≤ 760px 强制 `flex-direction: column`，列宽拖动条隐藏，模板按钮一并隐藏（此时三个模板没区别）——这是没跑起 JS 时的退路形态，新外壳下直接整屏一页一个事 |
| 卡片拖不动 / 一拖就滚页 | 浏览器先抢走手势去滚动 | 四边命中区与提手都加 `touch-action: none`；手指还需先走 8px 才真正抬起卡片，避免滑动起点误触（手机上干脆不给拖，这三行只适用于桌面触屏与退路形态） |
| 拖过去永远落在第一个面板 | 单栏下两栏都是整宽并上下叠，用 x 判断命中列必然命中第一栏 | 命中轴跟着布局走：`matchMedia('(max-width: 760px)')` 或单栏模板时改用 y 判定 |
| 拖到一半被系统手势打断，卡片飘在屏幕上 | `pointercancel` / 切窗口没收尾 | `pointercancel`、`blur` 均正常落位；加载时兜底把飘着的卡片接回归属列 |
| 底部被 iPhone 横条压住、下方一大片空白 | `100vh` 在地址栏收放时算错，且没留安全区 | `min-height` 用 `100dvh`（带回退），`padding` 叠 `env(safe-area-inset-*)`，`viewport-fit=cover` |
| 点输入框整个页面被放大 | iOS 在字号 < 16px 时聚焦自动缩放 | 手机上 `input / select` 统一 `font-size: 16px` |
| 任务列表里面套一层滚动 | 小屏里嵌套滚动难用 | 手机上取消 `max-height: 46vh`；新外壳下整页不滚，滚动落在卡片自己那一屏（`overflow-y: auto`） |
| 面板/登录框看着就是一片空白 | 卡片底色是 4% 透明，在大屏上靠阴影分层，小屏上根本看不出边界 | 窄屏下给 `.card` / `.auth-card` 描一圈 `inset 0 0 0 1px var(--line)` 细边 |
| 弹窗上半部分看不见也滚不到 | `.modal` 用 `grid + place-items: center`，内容高于视口时上面被裁掉 | 改成 `flex + overflow-y: auto + margin: auto`，这是“能滚动的安全居中” |
| 点完按钮像被按着不放、提手一直粘在最后一张卡片 | 触屏没有 hover，`:hover` 态点完不消失 | `@media (hover: none)` 关掉圆点缩放与 hover 底色，提手改为常驻 50% 透明度 |

浏览器地址栏输入局域网 IP（手机和电脑同一 WiFi）即可访问，端口由 `PORT` 决定，默认 3000。当前页记在 `localStorage` 的 `mView`，刷新后停在原来那一页。

### 文字对比度自适应

背景色变深就看不清字，是这个应用以前的问题，现在这样解决：

- 把背景图缩到 24×24 采样平均亮度 `luma = 0.299R + 0.587G + 0.114B`
- 卡片内可见亮度 ≈ `卡片浓度 × 卡片基色 + (1 − 卡片浓度) × (图片亮度 × 遮罩衰减)`，据此决定卡片内文字取深色还是浅色
- 卡片外的顶栏直接用背景亮度单独定色（`--fg-out`），并加文字投影
- 主题底色为深色时卡片基色自动切换，不会出现"深图 + 半透明白卡 + 深字"
- 判断不合你意时，直接用「文字颜色」锁定深色字 / 浅色字

## 🔒 数据与安全

- 密码用 `crypto.scryptSync(password, salt, 64)` 加盐哈希存储，明文不落盘
- token 为 `crypto.randomBytes(24)`，登录时重新生成
- 上传体积限制 1 MB，静态服务对路径做了 `normalize` + 前缀校验，防目录穿越
- 用户数上限 50（自用场景），`data/*.json` 为纯文本，**切勿提交到公开仓库**
- `.gitignore` 已排除 `data/`、`scripts/`、`*.log`、`.idea/`
- **MUSIC_U 等同网易云账号登录态**：拿到它就等于能操你那个号，所以只存 `data/settings.json`（不入 git）、接口不回传明文、网易云路由全部要登录。不想要这层就去听 QQ 音乐或内置轻音乐——两者都不需要任何 cookie

### 为什么重启不会丢账号（`lib/store.js`）

旧写法是“每个请求自己读文件 → 改 → 整体写回”，两个真实丢数据的坑就埋在这里：

| 坑 | 旧行为 | 现在的做法 |
| --- | --- | --- |
| 并发注册 | 两个请求各自读到同一份列表，后写的把先写的盖掉 → 账号静默消失 | 内存数组是唯一真源，“取→改→写盘”全在同步代码里完成 |
| 写一半断电 | `writeFileSync` 直接盖主文件，断电就留半截 JSON | 先写 `.tmp` + `fsync`，确认落盘后再原子改名替换 |
| 主文件坏了 | `catch` 里返回 `[]` → 下次保存直接清空整个文件 | 依次试 `主文件 → .tmp → .bak`，恢复后固化；坏文件改名 `.bad-时间戳` 留档，绝不静默清空 |
| 字段不齐 | 登录后 `user.salt` 踩空 | 载入时 `validate` 剔除不完整记录并在启动日志里说明剔了几条 |

启动时会做一次自检，日志直接报数：

```
[store] 数据自检：users.json 3 条 | tasks.json 12 条 | friends.json 2 条 | challenges.json 1 条 | settings.json 2 条
```

出过事则会写明从哪个文件恢复：“`[store] 已从 users.json.bak 恢复 users.json（3 条）`”。

旧版的“共享任务”（`shareWith` 字段）会在启动时一次性转成同任务挑战，被共享过的人当作**已接受邀请**的成员，日志会报 `[migrate] 已把 N 个旧“共享任务”转成同任务挑战`。

`npm test` 把上面四条坑当作断言跑一遍（用系统临时目录做 `DATA_DIR`，不碰真实 `data/`）。


## 🧪 开发方式

没有构建步骤，改完 `public/` 里的文件直接刷新浏览器。改了 `server.js` 或 `lib/` 需要重启进程。

两个约定在前端拆成 ES Module 之后变了：

- **不能双击 `index.html` 直开了**。浏览器对 `file://` 下的模块一律当跨源拒绝，必须起服务（`node server.js`）再访 `http://localhost:3000`。
- **`node --check` 对 `public/js/*.js` 会误报**。那个命令把 `.js` 当 CommonJS 解析，见到 `import` / `export` 就报语法错，而浏览器恰恰是按模块读它们的。所以前端语法自检走 `node --input-type=module --check`，或者直接跑 `node scripts/esm-check.js`（自己把每个模块当 ESM 编译一遍，顺带对账 import/export 是否对得上）。

```bash
node --check server.js lib/*.js lib/routes/*.js lib/music/*.js   # 后端语法
npm test                     # 全部端到端测试（自己拉起服务、临时目录，不碰 data/、不联网）
node test/qqmusic.test.js    # 只跑其中一层（四个测试文件各自独立）
```

后端四个测试文件互不依赖，也可以单独跑。前端没有测试框架，靠下面这套真机视口校验兜。

### 前端拆模块后的约束（改 `public/js/` 前先看一眼）

- **模块体只放声明，接线集中在 `init()`**。顶层那几行不再直接操作 DOM，否则谁先执行取决于 import 顺序，拆前拆后不等价。`js/main.js` 按拆前的文件顺序逐个调 `init()`，这个顺序就是当时的执行顺序。
- **跨模块的状态写一律走 setter**。ESM 的 import 绑定能读不能写，`layout`、`tasks`、`currentId` 这些会被整体重新赋值的变量，写的一方必须调导出侧的 `setXxx()`（见 `js/layout.js` 的 `setLayout`），否则会变成“各自拿着一份旧值”。
- **不是标识符形式的顶层声明也是声明**。`const { Spring, Ticker } = window.Phys` 这种解构必须留在模块顶层，被当成接线语句搬进 `init()` 就成了局部量，模块里的 `startDrag` 它们根本看不见 —— 拖拽当场报 `ReferenceError`。这类降级 `node --check` 与 import/export 对账都抽不到（那些名字不属于任何模块），所以 `scripts/esm-check.js` 专门盯这一条：`init()` 里声明的名字若被 `init()` 外面引用就是错。
- **桌面拖拽靠 `window.Phys`**：`public/physics.js` 是普通脚本，在 `index.html` 里排在 `<script type="module">` 之前同步执行，模块求值时它必然已就位（这也是 `panel-drag.js` 顶层能直接解构的原因）。
- **手机形态不能因为拆文件而回退**：`js/mobile-shell.js` 里 `if (!isMobile())` 决定的只是“给不给装拖拽热区”，CSS 那边 `.edge` / `.grip` 一并藏掉；两侧任何一侧改了都要重跑下面那个校验。

### 手机端改完怎么验

`public/css/mobile.css` 和外壳状态机改一处就可能崩掉另一处（比如给 `body` 加 flex 之后，子元素残留的 `margin: 0 auto` 会让整页宽度坍成 0），光看 CSS 看不出来。所以写了个一次性校验脚本 `scripts/mobile-check.js`（`scripts/` 在 `.gitignore` 里，不入库）：

```powershell
node server.js                      # 先起着服务（默认 3000）
node scripts/mobile-check.js        # 拉起 Edge 无头，跑完自动退出；有失败则 exit code 1
```

它用 DevTools 协议模拟手机视口，不需要额外装任何依赖（Node 22+ 自带全局 `WebSocket`）。断言清单：

| 范围 | 断言 |
| --- | --- |
| 三个视口 360×640 / 390×844 / 430×932 | `body` 打上 `mobile` 类；整页 `scrollHeight/Width` 不得超过视口；时钟页与倒计时页内容不超出卡片自身；没有任何面板横向顶破视口 |
| 抽屉 | 整屏盖住宽高、八个格子都在视口内且 ≥40px |
| 全屏 sheet | 音乐弹层铺满整屏、「完成」按钮在视口内、滚动只发生在弹层内部；抽屉里点「同任务挑战」同样开成满屏 sheet，里面有一句「刚刚更新」而不是刷新按钮 |
| 任务行尺寸 | 每个视口都量自己造的那条任务：行尾四个按钮尺寸完全一致且 ≥36px、行高 ≥56px、任务名里不再有 `↻` 那个像重新加载的符号 |
| 播放条与队列 | 条子整宽贴底；队列面板展开时不挡住 ⏮ ▶ ⏭；有播放条时列表底部留出让位高度。这几项**不赌上游音乐接口**：往 `localStorage` 注入一份假队列再刷新，走 `restoreQueue` 那条路把播放条摆出来 |
| 导航 | 点抽屉条目后抽屉关闭且切到目标页；点左上角标题回时钟页 |
| CDN 不可达（`Network.setBlockedURLs` 挡 `*jsdelivr*`） | 没 Alpine 也能开抽屉、切好友页、开背景 sheet |
| 双绑定 | 把 `window.fetch` 包一层计数，数一次点击发出几个 `/queue` 请求：顶栏与抽屉都要求**恰好 1 个**（叠了两层绑定就是 2 个）。不数 `play()`：那个既受自动播放策略影响、又受上游有没有曲目影响 |
| 模块加载 | 盯 `Runtime.exceptionThrown` 与 `source === javascript` 的错误日志，再加 `Network.responseReceived` 里 `/js/*.js` 的响应码≥400 ——ESM 拆坏了不会抛异常，只会默默白屏；资源类报错（favicon 404、脚本自己触发的 409/401）单独打 INFO，不混进页面错误 |
| 桌面回归 1280×800 | 不打 `mobile` 类、汉堡与抽屉 `display: none`、仍是两列且任务栏在右、顶栏六入口（含新的「⚑ 挑战」）与拖拽热区都在、标题没被 Alpine 改掉、无横向滚动 |
| 桌面拖拽（真按真拖） | 用 CDP `Input.dispatchMouseEvent` 在 `#panel-tasks .edge-l` 上按下、向左拖、释放，断言 `layoutV2` 存档真的变了、任务卡进了 `col-a`、`body` 上没有残留的 `.card`，跑完清存档复原 |
| 桌面新交互 | 行尾四按钮统一 36×36 且 `.task-top` 的 `column-gap` 为 12px；点行里的时间那一行（不是按钮）直接进专注；点 `▶` 与整行同一条路径且两个字形靠 opacity 交接；暂停后大数字带 `paused`、computed transform 是 `matrix(0.97…)`、过渡是 150ms ease-out 且含 transform；挑战中心默认收起，点开后用一张临时 `.ch-card` 探针量 `-webkit-line-clamp: 2` / `display: -webkit-box` / 不是 `text-overflow: ellipsis` / 不是 `white-space: nowrap` / 卡高与 scrollHeight 无差 / 摘要行 `tabular-nums`；拿 12 秒 `fetch` 计数窗口断言 `/api/tasks` 最多 1 次（证明不再是 5 秒一轮），跑完按名字把自己造的任务扫干净 |

### 改完就推

```bash
git add -A
git commit -m "feat: ……"
git push                     # 凭据在系统凭据管理器里，命令行不出现 token
```

首次把凭据交给系统（任选其一，之后的推送都不必再带 token）：

- 直接 `git push`，Git Credential Manager 会弹浏览器授权一次；
- 或用 PAT：`printf "protocol=https\nhost=github.com\nusername=<用户名>\npassword=<token>\n\n" | git credential approve`。

> 不要把 token 写进 remote URL（会明文留在 `.git/config`），也不要给它加 `repo` 以外的写权限。

## 🛠 已知限制

- JSON 文件存储靠“内存真源 + 原子写盘”，几十用户够用；真要上百并发就该换数据库
- 数据只在启动时读盘，服务跑着的时候手工改 `data/*.json` 不会被发现（重启才会）
- 同任务挑战只排行与点赞，不做协作控制（同一个目标各自打卡，谁也不能改谁的计时）
- 音乐走网易云 / QQ 音乐**非官方**网页端接口，随时可能改版或限流；已把解析与网络分层、取不到地址就自动跳过，但长期稳不保证。不想用就把音乐面板晾着，不影响计时功能
- **QQ 音乐只有“内置轻音乐 + 单曲搜索”**：没有 QQ 登录态时歌单接口全报 -3002 / 404 / 500003，读不到；付费与会员曲目也拿不到地址（只能自动跳过）。要放自己的歌单请用网易云
- 解锁自己的歌单与 VIP 曲目只能靠粘 `MUSIC_U`（网易云网页端 `F12` 取），**没有扫码 / 验证码登录**；内置轻音乐、公开歌单与 QQ 音乐都不需要它
- 背景图以 dataURL 存在浏览器本地，大图（约 >2 MB）可能超出 `localStorage` 配额，会提示改用外链
- 无 WebSocket：好友进度与挑战名次靠前端轮询刷新（每 30 秒一次，且只在标签页可见时拉，回到前台立即补一次）
- 手机端外壳依赖 CDN 上的 Alpine.js（本项目唯一一处第三方运行时）。CDN 不通时 `onerror` 会退回原生事件绑定，抽屉与切页照常能用；连 JS 都禁用的话，退成单栏整页滚动的老布局，功能不丢但手机上是"挤窄的桌面"
- 手机上不给面板拖拽与列宽调整（整屏一屏一个事，没有可拖的东西）；要改布局得回桌面端
- 手机形态按 360×640 / 390×844 / 430×932 三个视口做过无头校验（零溢出），折叠屏外屏、横屏与系统字号放大未覆盖
- 拖拽的惯性 / 果冻手感只在桌面指针事件下调过；触屏继承了同一套物理，但未逐机型验证多指与系统手势冲突

## 🔭 可扩展方向

- 存储层换成 SQLite（Node 22+ 自带 `node:sqlite`，不新增 npm 包）或 Postgres，顺带解决部署易失问题
- 拖拽物理参数（刚度 / 阻尼 / 质量）暴露成设置项，支持“干脆”与“果冻”两档手感
- 学习/专注时长统计与周视图报表
- 好友排行榜、打卡日历
- WebSocket 或 SSE 推送替代轮询
- 网易云扫码登录：自己实现 weapi 的 RSA+AES 签名拿 unikey，二维码用纯 JS 绘到 `<canvas>`（不引第三方生图服务），成功后自动写 `MUSIC_U`
- QQ 音乐的歌单：需要先拿到 QQ 登录态（p_skey / qm_keY），拿到后就能复用同一套 `midurlinfo` 取地址逻辑，并给 `/api/qq/*` 补上 playlist / mine 两个路由
- PWA（离线 + 桌面安装）
